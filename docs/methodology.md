# 방법론과 구현 범위

## 원본 기록과 실행기

`notebooks/subway_route_optimization.ipynb`는 원본 Colab의 33개 셀 소스를 같은 순서로 보존합니다. 설치 로그, 그림 등 셀 출력과 실행 횟수·Colab 임시 메타데이터는 제거했습니다.

`src/optimize_routes.py`는 마지막 `개체 개선 알고리즘` 셀을 함수로 감싼 실행기입니다. 경로를 `--data-dir`로 받고, 설치 명령은 requirements 파일로 옮겼습니다. 반복 횟수, 시드, 그림 표시와 저장을 옵션으로 추가했으며, 입력 누락과 유효 후보가 없는 경우를 명시적으로 처리합니다. 원본의 연구 함수와 적합도 정의는 유지했습니다.

시드를 지정하면 Python·NumPy 난수를 설정하고, 미포함 역 목록을 정렬해 순회합니다. 시드를 생략하면 원본처럼 비결정적입니다. 같은 시드도 입력 버전과 패키지 버전이 다르면 같은 결과를 보장하지 않습니다. 원본의 패키지 전체 버전과 시드는 기록되어 있지 않습니다.

## 최종 노선 생성

1. 엣지 Excel에서 역명과 좌표를 읽어 무방향 그래프를 구성합니다.
2. 2호선 순환 경로를 구성하고, 필요한 인접 엣지를 추가합니다.
3. 후보마다 기하 거리에 `0.1 ~ 1.9`의 난수 배수를 적용합니다.
4. 사용한 엣지를 피하며 다음 종착역 쌍을 연결합니다.

| 노선 표시 | 출발역 | 도착역 |
| --- | --- | --- |
| 1 | 천왕 | 지축 |
| 3 | 역곡 | 회룡 |
| 4 | 하남검단산 | 방화 |
| 5 | 독바위 | 신내 |
| 6 | 불암산 | 남태령 |
| 7 | 개화 | 중앙보훈병원 |
| 8 | 수락산 | 마천 |
| 9 | 암사 | 모란 |

5. 포함되지 않은 역을, 경로의 기하 거리 증가량이 가장 작은 위치에 삽입합니다. 이 초기 삽입 단계에서는 2호선을 제외합니다.
6. 초기 후보에서 35도 미만의 각도를 제외하고 적합도를 계산합니다. 원본 일부 주석에는 60도로 쓰여 있으나 실제 기본 인자는 35도입니다.
7. 최고 후보를 선택해 60도 미만의 꺾임을 우선 대상으로 국소 개선을 수행합니다. 점수가 기존 이상인 후보를 채택합니다.

## 적합도

`fitness = 1.0 * OD_score + 2.5 * node_score + 0.1 * length_penalty + 0.013 * angle_penalty`

| 항목 | 마지막 셀의 실제 계산 |
| --- | --- |
| OD | 각 노선 안의 모든 `i < j` 역 쌍을 조회. 정방향 키가 있으면 이를 쓰고, 없을 때만 역방향 키를 사용 |
| 시설 | 각 경로에 등장하는 역의 시설 점수를 합산. 여러 노선에 등장한 역은 여러 번 포함 |
| 길이 | 2호선 외 노선의 경로 역 수가 20~50 범위를 벗어나면 초과·부족분의 제곱을 음수로 반영 |
| 각도 | 90도 미만 꺾임의 부족분과 연속 두 각도의 차이를 합산한 뒤 음수로 반영. 원본은 역 수가 4 미만인 경로를 건너뜀 |

길이·각도 패널티 자체가 음수이므로 양의 계수를 더하는 식입니다. 최종 셀은 이미 집계한 시설 점수 파일을 읽으며 시설을 다시 수집하지 않습니다.

## 결과 해석과 남은 과제

이 실험의 점수는 자체 목적함수의 값입니다. 목적함수가 개선되더라도 전역 최적해나 실제 이동시간·수송량의 개선을 입증하지는 않습니다.

원본을 보존한 이번 실행기에서도 다음 특성을 고려해야 합니다.

- **좌표 단위**: 경위도에 유클리드 거리와 각도를 직접 적용합니다. 실제 거리·각도 비교에는 투영 좌표계나 지리 거리 처리가 필요합니다.
- **탐색의 최적성**: 가중치를 원래 거리보다 작게 만들면서 휴리스틱은 원래 기하 거리를 사용하므로, 현재 A* 계열 탐색의 최단경로 보장을 주장할 수 없습니다.
- **수요 집계**: 역명만으로 OD 사전을 만들면서 같은 키의 마지막 행을 사용합니다. 환승 경로, 배차와 혼잡을 평가하지 않으며, 경로·노선 간 반복 등장도 고유 승객 단위로 제거하지 않습니다.
- **국소 개선의 제약**: 원본은 2호선을 역 제거 대상에서 제외하지만 재삽입 대상으로는 제외하지 않습니다. 따라서 개선 후 2호선 고정성을 보장하지 않습니다. 초기의 35도 조건도 개선 후 다시 검사하지 않습니다.
- **후보 재배치**: 한 번 모은 후보 인덱스를 재사용하므로 앞선 이동 후 인덱스가 달라질 수 있습니다. 노드 보존, 경로 중복, 엣지 존재 및 전체 연결성에 대한 엄밀한 검사가 추가로 필요합니다.
- **그림과 실행 가능한 노선망**: 미포함 역 삽입·역 제거 후 모든 연결을 그래프와 일관되게 갱신하거나 건설 가능성을 확인하지는 않습니다. 시각화된 연결만으로 실제 운행 가능한 노선망을 확정할 수 없습니다.

이 사항은 원본 연구 코드의 후속 개선 과제입니다. 실험 기록을 옮기는 과정에서 목적함수나 탐색 규칙을 다른 알고리즘으로 바꾸지는 않았습니다.
